# Decisões do MVP

## Começar pela planilha

A planilha já atendia à consulta, aos cálculos e às correções. Criar banco de dados, API e aplicativo antes de validar a rotina aumentaria o custo sem provar que o fluxo era útil.

## Manter a evidência fora da planilha

Fotos podem deixar a planilha pesada e expor informações desnecessárias. Por isso, os arquivos ficam no Drive e a base mantém apenas a referência necessária para a conferência.

## Preservar o texto original

Cupons usam abreviações e descrições inconsistentes. A normalização melhora a busca, mas o texto original continua disponível para mostrar de onde veio a interpretação.

## Tratar incerteza como dado

`Precisa confirmar` e `Divergência provável` não são falhas do fluxo. São estados necessários para impedir que uma leitura incompleta pareça definitiva.

## Não processar dados pessoais

CPF, forma de pagamento e outros dados que não ajudam na comparação devem ser ignorados. O objetivo é conferir produtos e preços.

## Adiar uma aplicação própria

O MVP valida primeiro a leitura, as regras e o histórico. Uma aplicação dedicada só faz sentido quando os testes mostrarem quais etapas ainda exigem trabalho manual e quais integrações trazem ganho real.
